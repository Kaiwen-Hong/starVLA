## 关键设计决策

### 为什么 unnorm_key 是 `"new_embodiment"` 而不是 `"robotwin_ee"`

训练时 `robotwin_ee` 未注册到 `ROBOT_TYPE_TO_EMBODIMENT_TAG`，因此 training
时打印 `Warning: Robot type robotwin_ee not found in ROBOT_TYPE_TO_EMBODIMENT_TAG,
using EmbodimentTag.NEW_EMBODIMENT as default`，最终 `dataset_statistics.json`
中的 key 为 `"new_embodiment"`。

### EE 空间 vs 关节空间的差异

| 项目 | 关节空间 (14D) | EE 空间 (16D) |
|------|--------------|--------------|
| action_dim | 14 | 16 |
| state 来源 | `observation["joint_action"]["vector"]` | `observation["endpose"]` |
| 动作 reorder | `[[0,1,2,3,4,5,12,6,7,8,9,10,11,13]]` | **不需要** |
| take_action | `TASK_ENV.take_action(action)` | `TASK_ENV.take_action(action, action_type='ee')` |
| unnorm_key | `"robotwin"` | `"new_embodiment"` |
| 服务器端口 | 5694 | 5695 |

### EE 动作格式 (16D)

| 索引 | 含义 | norm_mode |
|------|------|-----------|
| 0-2 | left_pos (xyz) | min_max |
| 3-6 | left_quat (wxyz) | min_max |
| 7 | left_gripper | binary (mask=False) |
| 8-10 | right_pos (xyz) | min_max |
| 11-14 | right_quat (wxyz) | min_max |
| 15 | right_gripper | binary (mask=False) |

模型输出顺序与 RoboTwin EE 期望顺序一致，**不需要 reorder**。

### action_chunk_size

`future_action_window_size = 15`，因此 `action_chunk_size = 16`。
每 16 步请求一次新动作块。

## 常见问题排查

| 现象 | 原因 | 解决 |
|------|------|------|
| `FileNotFoundError: Dataset path ... does not exist` | 训练时 CustomEE_v32/ 未先 split | 运行 `bash scripts/split_custom_v0309_v32_ee.sh` |
| `place_object_stand_wp4 not in step limit file, set to 1000` | _eval_step_limit.yml 缺失 wp4/wp5 | 已修复，git pull 即可 |
| `unnorm_key 'robotwin_ee' not in stats, using 'new_embodiment'` | 正常现象，自动 fallback | 无需处理（deploy_policy_ee_v3x.yml 已设 unnorm_key: new_embodiment） |
| 服务器启动超时 (>90s) | 模型加载慢 | 增大 `SERVER_WAIT` 变量：`SERVER_WAIT=180 bash run_eval_v3031.sh` |
| `policy/starVLA_ee` module not found | 未复制策略模块 | Step 3: `cp -r .../starVLA_ee ar-research-kempner/policy/` |
| WebSocket 连接被拒 | 服务器用了错误端口或未启动 | 确认 port=5695；`lsof -ti tcp:5695` 检查进程 |
| `STARVLA_ROOT` 路径错误 | starVLA repo 不在默认路径 | `export STARVLA_ROOT=/your/path/to/starVLA` |
